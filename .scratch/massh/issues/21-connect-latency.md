# 21: Ускорить подключение к Server

**What to build:** Подключение к 192.168.0.19 занимает 3–4 с, `ssh` в терминале пользователя в разы быстрее. Сначала замеры, затем правка. Цель: менее ~300 мс, когда `ControlMaster` уже жив.

**Blocked by:** —

**Status:** done

**Что известно:** в `~/.ssh/config` нет `ProxyJump`/`ControlMaster` для хоста. Ключ `~/.ssh/id_ed25519`. Из окружения агента `ssh -o BatchMode=yes 192.168.0.19 true` занял 10.0 / 2.2 / 2.0 с, так что часть задержки может быть на стороне сети/sshd, а не massh; сверить с `ssh` из терминала пользователя. Подозрения в massh: вкладка не берёт готовый `ControlMaster`, повторный `ssh -G` на каждое подключение.

- [x] Замеры: `ssh` из терминала, из massh (вкладка), из massh (наблюдение)
- [x] Названа причина разницы
- [x] Вкладка при живом Master открывается менее ~300 мс

**Замеры (контейнер Ubuntu, задержка 400 мс):** `ssh` напрямую 4,5 с; через мастер 1,25 с. На 192.168.0.19 из окружения агента `ssh … true` занимал 2–10 с, то есть основная часть — сеть или sshd на сервере.

**Сделано:** вкладки ходят через свой мастер на Server (`SSHCommand.tabControlPath`, `ControlPersist` 60 с), его заранее открывает `warmUp` при выборе Server (в `BatchMode`, без пароля молча не открывается). Он отделён от туннеля Inspector: SIGTERM мастеру обрывает сессии через него (проверено), а Inspector закрывает свой при смене Server. В приложении Connect открыл сессию за ~1,5 с вместо 4,5+. Тесты `TerminalCommandTests`, `terminalTabOutlivesTheInspectorSession`, `WarmUpTests`.

**Не проверено:** на самом 192.168.0.19.
