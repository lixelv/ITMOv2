# 24: Снизить потребление CPU у Agent (оптимизация на Go)

**What to build:** Agent потребляет около 4 % CPU, пока massh к нему подключён. Снизить нагрузку, оставаясь на Go: переписывать на Rust не нужно, основная нагрузка — системные вызовы к `/proc`, а не код на Go. Сначала замер, потом правки, потом замер снова.

**Blocked by:** —

**Status:** done

**Что известно (по коду, без профиля):** раз в секунду для **каждого** Process `collect/processes.go`:
- читает `/proc/<pid>/stat`, `/proc/<pid>/status`, `/proc/<pid>/cmdline`;
- делает `ReadDir("/proc/<pid>/fd")` и `Readlink` на каждый дескриптор, чтобы найти владельцев портов;
- заново разбирает `/etc/passwd`.

На сервере с сотнями Process и Docker или СУБД это тысячи системных вызовов в секунду, и большую часть времени ядро тратит на генерацию `/proc`. Статистику Docker трогать не нужно: `one-shot=true` уже стоит, работу делает `dockerd`.

**План, по убыванию эффекта:**
1. Сканировать `fd` редко: таблицу «inode сокета → Process» пересобирать раз в 10–30 с или когда в `/proc/net/tcp*`/`udp*` появился незнакомый inode слушающего порта.
2. Читать на Process только `stat`: utime, stime и RSS (поле 24, в страницах) уже там. UID брать из владельца каталога `/proc/<pid>`; `cmdline` и пользователя кешировать по паре (pid, starttime), чтобы переиспользование PID не путало данные.
3. Кешировать `/etc/passwd`, перечитывать при смене mtime.
4. Переиспользовать буферы чтения вместо `os.ReadFile` и преобразования в `string`.
5. Опционально: отправлять список Process раз в 2–3 с, Overview по-прежнему раз в секунду (видно в интерфейсе, решить отдельно).

**Замер:** `BenchmarkCollectLive` в Ubuntu-контейнере с 312 Process и ~10 700 дескрипторами, 45 слушающих портов. Базовая линия 16 мс на сбор (56 % ядро, 44 % Go), 8,2 МБ и 114 000 аллокаций.

**Сделано:** владельцы портов кешируются и пересчитываются только при новом слушающем сокете и раз в 30 с; на Process за сбор читается только `stat` (RSS оттуда), пользователь и команда — один раз на Process (по pid + starttime); `/etc/passwd` перечитывается при изменении. В одном прогоне CPU на 60 сборов 2,73 с → 0,30 с (в ~9 раз), аллокаций 114 000 → 5 400, памяти 8,2 → 1,3 МБ. Agent 0.1.1: massh предложит обновить установленные.

**Не сделано (не понадобилось):** переиспользование буферов и редкая отправка списка Process. **Не проверено:** `pidstat` на 192.168.0.19 — Agent там не установлен.
