# massh — SSH-клиент для macOS со сведениями о серверах

Status: ready-for-agent

## Problem Statement

Я подключаюсь к своим Linux-серверам через обычный терминал и `ssh`. Чтобы понять, что происходит на сервере, приходится сначала гадать, жив ли он, потом подключаться и вручную запускать `ss`, `systemctl`, `docker ps`, `docker stats`, `free`, `df`, `top`. Картина собирается из кусков, на каждом сервере заново, и пропадает, как только я закрываю сессию. В списке серверов из `~/.ssh/config` не видно ни доступности, ни того, что на сервере запущено.

## Solution

massh — нативное приложение для macOS в стиле Xcode с Liquid Glass. Слева — Server List из `~/.ssh/config` с отметками Online / Offline / Unknown. В центре — вкладки терминала (системный `ssh`, всё как в обычном терминале). Справа — инспектор выбранного Server: обзор системы, порты, Process и Container, обновляемые раз в секунду. Сведения отдаёт Agent — маленький демон на Go, который massh с моего согласия ставит на Server; в простое он ничего не делает, а приложение достаёт до него только через SSH-туннель. Серверы можно добавлять, править и удалять прямо в massh — изменения пишутся в тот же `~/.ssh/config`.

## User Stories

### Server List

1. As a пользователь, I want видеть в сайдбаре все Server из `~/.ssh/config`, so that не заводить их второй раз.
2. As a пользователь, I want видеть Server из файлов, подключённых через `Include`, so that мой разбитый на части конфиг работает целиком.
3. As a пользователь, I want чтобы блоки-шаблоны (`Host *`, `Host *.prod`) не попадали в Server List, so that в списке были только реальные машины.
4. As a пользователь, I want видеть рядом с каждым Server отметку Online / Offline / Unknown, so that понять, к кому вообще можно подключиться.
5. As a пользователь, I want чтобы статус проверялся сразу при открытии окна, so that не ждать первой проверки.
6. As a пользователь, I want чтобы статус обновлялся каждые 30 секунд, пока окно открыто, so that список оставался актуальным.
7. As a пользователь, I want чтобы статус перепроверялся при пробуждении Mac, so that не смотреть на устаревшие отметки после сна.
8. As a пользователь, I want чтобы недоступный Server помечался Offline не позже чем через 3 секунды, so that список не «висел».
9. As a пользователь, I want чтобы Server за Bastion проверялся через этот Bastion, если с ним уже есть соединение, so that такие серверы не помечались Offline по ошибке.
10. As a пользователь, I want чтобы Server за Bastion без открытого соединения с Bastion показывался как Unknown, so that отличать «недоступен» от «не могу проверить».
11. As a пользователь, I want чтобы статус не зависел от наличия Agent, so that он работал для любого Server.
12. As a пользователь, I want чтобы изменения `~/.ssh/config`, сделанные снаружи, подхватывались в Server List, so that редактирование в vim и в massh не расходилось.

### Редактирование Server

13. As a пользователь, I want добавить Server с полями имя, HostName, User, Port, IdentityFile, ProxyJump, so that не открывать конфиг руками.
14. As a пользователь, I want изменить эти шесть полей у существующего Server, so that поправить адрес или пользователя.
15. As a пользователь, I want чтобы остальные директивы блока `Host` при правке сохранялись нетронутыми, so that massh не ломал мои настройки.
16. As a пользователь, I want чтобы комментарии, порядок блоков и отступы в `~/.ssh/config` сохранялись при любой записи, so that файл оставался моим.
17. As a пользователь, I want чтобы перед каждой записью делался бэкап `~/.ssh/config.massh.bak`, so that откатить неудачную правку.
18. As a пользователь, I want удалить Server только после подтверждения, so that не потерять запись случайно.
19. As a пользователь, I want чтобы Server из `Include`-файлов были видны, но не редактировались, so that massh не писал в файлы, которыми я управляю отдельно.
20. As a пользователь, I want понятную ошибку, если имя нового Server уже занято, so that не получить два блока с одним именем.

### Терминал

21. As a пользователь, I want открыть терминальную вкладку к Server двойным кликом или кнопкой в тулбаре, so that подключаться в один жест.
22. As a пользователь, I want чтобы в терминале работал мой системный `ssh` со всеми ключами, ssh-agent, ProxyJump и known_hosts, so that massh вёл себя как обычный терминал.
23. As a пользователь, I want открыть несколько вкладок к одному Server, so that параллельно смотреть логи и работать.
24. As a пользователь, I want держать вкладки к разным Server одновременно, so that переключаться между машинами.
25. As a пользователь, I want чтобы при переключении на вкладку инспектор показывал её Server, so that сведения соответствовали тому, где я работаю.
26. As a пользователь, I want видеть, что сессия во вкладке завершилась, so that не печатать в мёртвый терминал.

### Инспектор

27. As a пользователь, I want открыть инспектор Server кликом в сайдбаре даже без терминальной вкладки, so that посмотреть сведения, не заходя на сервер.
28. As a пользователь, I want скрывать и показывать инспектор кнопкой в тулбаре, как в Xcode, so that освобождать место под терминал.
29. As a пользователь, I want чтобы сведения обновлялись раз в секунду, so that видеть происходящее вживую.
30. As a пользователь, I want видеть на вкладке «Обзор» ОС, ядро, uptime и load average, so that понять, что это за машина.
31. As a пользователь, I want видеть модель CPU, число ядер, общую загрузку и загрузку по ядрам, so that заметить перегрузку.
32. As a пользователь, I want видеть всего и занято для RAM и swap, so that понять, хватает ли памяти.
33. As a пользователь, I want видеть занято/всего для каждой точки монтирования, so that не пропустить заканчивающийся диск.
34. As a пользователь, I want видеть входящую и исходящую скорость сети, so that заметить необычный трафик.
35. As a пользователь, I want видеть графики CPU, RAM и сети за время, пока инспектор подключён, so that видеть тренд, а не одно число.
36. As a пользователь, I want видеть на вкладке «Порты» протокол, адрес и порт каждого слушающего сокета, so that знать, что открыто.
37. As a пользователь, I want видеть, какой Process (PID и имя) или какой Container держит порт, so that понять, кто его занял.
38. As a пользователь, I want видеть на вкладке «Процессы» PID, имя, пользователя, CPU %, RAM и полную команду каждого Process, so that найти прожорливый процесс.
39. As a пользователь, I want чтобы в списке Process были и системные процессы, но не было потоков ядра, so that список был полным, но читаемым.
40. As a пользователь, I want сортировать списки портов, Process и Container по любой колонке, so that быстро найти нужное.
41. As a пользователь, I want видеть на вкладке «Контейнеры» имя, образ, статус, CPU %, RAM (занято и лимит) и порты каждого Container, so that понимать нагрузку от Docker.
42. As a пользователь, I want видеть «Docker не установлен», если на Server нет Docker, so that не гадать, почему список пуст.
43. As a пользователь, I want видеть, что у Server нет Agent, и предложение его установить, so that понять, почему сведений нет.
44. As a пользователь, I want видеть понятное состояние, если соединение с Agent пропало, so that не принимать застывшие цифры за живые.
45. As a пользователь, I want чтобы инспектор переподключался к Agent сам после обрыва, so that не кликать заново.

### Agent

46. As a пользователь, I want чтобы massh спрашивал «Установить Agent на <server>?» перед установкой, so that ничего не ставилось без моего ведома.
47. As a пользователь, I want вводить пароль sudo сам в терминальной вкладке во время установки, so that massh никогда не видел и не хранил мой пароль.
48. As a пользователь, I want чтобы massh сам выбирал бинарник Agent под amd64 или arm64, so that не думать об архитектуре.
49. As a пользователь, I want чтобы Agent работал как systemd-сервис от отдельного пользователя без полного root, so that ограничить последствия уязвимости.
50. As a пользователь, I want чтобы Agent запускался сам после перезагрузки Server, so that не переустанавливать его.
51. As a пользователь, I want чтобы Agent в простое не потреблял CPU, so that он не мешал моим сервисам.
52. As a пользователь, I want чтобы Agent слушал только localhost, so that ничего не торчало в интернет и не надо было трогать файрвол.
53. As a пользователь, I want чтобы Agent не хранил историю метрик, so that он не копил данные и не ел диск.
54. As a пользователь, I want видеть плашку «Обновить Agent», если его версия старше версии в massh, so that держать Agent актуальным.
55. As a пользователь, I want обновлять Agent тем же способом, что и устанавливать, so that не учить второй процесс.
56. As a пользователь, I want удалить Agent с Server из контекстного меню, so that убрать его, когда он не нужен.
57. As a пользователь, I want отказаться от установки Agent и всё равно пользоваться терминалом и статусом, so that massh был полезен и без Agent.

### Внешний вид

58. As a пользователь, I want чтобы massh выглядел как родное приложение Apple в духе Xcode, so that он не выбивался из системы.
59. As a пользователь, I want чтобы интерфейс использовал Liquid Glass и стандартные контролы, so that он соответствовал macOS 26.
60. As a пользователь, I want поддержку светлой и тёмной темы системы, so that massh следовал моим настройкам.

## Implementation Decisions

- Три модуля: **MasshCore** (Swift Package, рабочая логика, без SwiftUI), **MasshApp** (SwiftUI-приложение), **Agent** (Go-модуль). Сначала фиксируется формат Snapshot и Swift-модели; затем параллельно — MasshApp на фейковых данных, Agent и MasshCore; в конце — соединение частей.
- **Платформа приложения:** macOS 26+, Swift + SwiftUI, Liquid Glass, стиль Xcode (ADR 0003). Без App Sandbox, вне Mac App Store, локальная сборка без нотаризации (ADR 0006).
- **Раскладка окна:** трёхколоночный split view — сайдбар (Server List), рабочая область (вкладки терминала), инспектор (вкладки «Обзор», «Порты», «Процессы», «Контейнеры»). В тулбаре: подключиться, добавить Server, показать/скрыть инспектор.
- **Хранилище Server — `~/.ssh/config`** (ADR 0002). Парсер сохраняет файл без потерь (комментарии, порядок, отступы, неизвестные директивы); запись меняет только нужный блок `Host`; перед записью — бэкап `~/.ssh/config.massh.bak`. `Include` читается, но такие Server только для чтения. Шаблоны с `*`/`?` в Server List не попадают. Редактируемые поля: имя, HostName, User, Port, IdentityFile, ProxyJump. Внешние изменения файла отслеживаются.
- **Доступность:** TCP-подключение к SSH-порту, таймаут 3 с; проверка при открытии окна, каждые 30 с и при пробуждении Mac. Server с ProxyJump проверяется через существующее ControlMaster-соединение с Bastion (`ssh -W`); если его нет — Unknown. От Agent не зависит.
- **SSH — только системный `/usr/bin/ssh`** (ADR 0004). Терминал — SwiftTerm с процессом `ssh <server>`. Служебные действия (установка Agent, туннель) идут через `ssh` с ControlMaster, переиспользуя соединение.
- **Agent** (ADR 0001, ADR 0005): статический Go-бинарник для linux/amd64 и linux/arm64, бинарники лежат внутри приложения. systemd-юнит `massh-agent.service`, пользователь `massh`, группа `docker`, capabilities `CAP_SYS_PTRACE` и `CAP_DAC_READ_SEARCH`. Слушает WebSocket на `127.0.0.1:12092`; приложение ходит через `ssh -L` поверх ControlMaster. Без TLS и токенов — защиту даёт SSH.
- **Поведение Agent:** без подключённых клиентов не собирает данные (≈0 CPU); при подключённом клиенте собирает и отправляет Snapshot раз в секунду; истории не хранит. Потоки ядра исключаются из Process. Если Docker нет — сообщает об этом в Snapshot.
- **Требования к Server:** Linux с systemd, amd64 или arm64. Docker — опционально.
- **Контракт Snapshot (WebSocket, JSON, одно сообщение раз в секунду):** версия формата и версия Agent; время снимка; обзор (ОС, ядро, uptime, load average; CPU — модель, ядра, загрузка общая и по ядрам; RAM и swap — всего/занято; диски — точка монтирования, всего/занято; сеть — скорость входящая/исходящая); порты (протокол, адрес, порт, владелец — Process с PID и именем или Container); Process (PID, имя, пользователь, CPU %, RAM, команда); Container (имя, образ, статус, CPU %, RAM занято/лимит, порты) либо признак «Docker не установлен». CPU % и сетевые скорости считаются Agent между соседними снимками. Изменение формата — через версию.
- **Публичное API MasshCore** (на нём же UI работает с фейками): хранилище Server (прочитать список, добавить, изменить, удалить, наблюдать изменения); монитор доступности (поток статусов по Server); сессия наблюдения за Server (поток Snapshot и состояний «нет Agent», «Agent устарел», «соединение потеряно», «переподключение»); операции с Agent (установить, обновить, удалить — каждая отдаёт команду для терминальной вкладки).
- **Установка/обновление/удаление Agent:** только после подтверждения пользователя; бинарник загружается под нужную архитектуру, установщик запускается в терминальной вкладке, sudo-пароль вводит пользователь. Версия Agent приходит в Snapshot; если она старше версии в приложении — плашка «Обновить Agent».
- **Графики** строятся в приложении из Snapshot, полученных за время текущего подключения инспектора.

## Testing Decisions

- Хороший тест проверяет внешнее поведение через публичный шов, а не внутренности: что получилось в файле, что пришло в Snapshot, какой статус отдал монитор — а не какие функции вызывались.
- **Шов 1 — контракт Snapshot.** Agent генерирует эталонные JSON-Snapshot (обычный, без Docker, с пустыми списками, с предыдущей версией формата); MasshCore обязан их декодировать. Эталоны общие для обеих сторон — так части гарантированно стыкуются.
- **Шов 2 — публичное API MasshCore**, через TDD:
  - `~/.ssh/config`: чтение и запись без изменений побайтно совпадают с исходником; правка одного Server меняет только его блок; `Include`, шаблоны, комментарии, неизвестные директивы, дубликаты имён, бэкап.
  - доступность: Online/Offline/Unknown на локальных тестовых сокетах, таймаут, Server за Bastion.
  - сессия наблюдения: поток Snapshot и переходы состояний на фейковом WebSocket-сервере.
- **Шов 3 — Agent снаружи.** Интеграционные тесты: Agent запускается в Linux-контейнере (OrbStack, systemd и Docker внутри), тест подключается по WebSocket и проверяет Snapshot, отсутствие сбора без клиентов, работу без Docker. Плюс Go-тесты сбора данных на фикстурах `/proc`.
- **MasshApp** проверяется SwiftUI Previews на фейковых Snapshot и фейковом хранилище Server; отдельных UI-тестов в первой версии нет.
- Prior art в репозитории отсутствует — это первый код проекта.

## Out of Scope

- Серверы не на Linux и Linux без systemd (для них — только терминал и статус).
- История метрик на Server, алерты, уведомления.
- Управление сервисами и контейнерами (запуск, остановка, рестарт, логи) — только просмотр.
- Свой SSH-стек, SFTP-браузер файлов, перенос файлов.
- Открытый наружу порт Agent, TLS и токены Agent.
- Редактирование директив `~/.ssh/config` сверх шести полей и запись в `Include`-файлы.
- Фильтрация «системных» Process.
- Mac App Store, App Sandbox, нотаризация, автообновление приложения.
- iOS/iPadOS и другие платформы.
